Project Overview

Research date: 24 October 2026 | Revision: 445eb11

Recommendation

Recompose the existing system into one installable Python application around its deterministic financial semantics and one execution owner.

Key Features

Tiered Architecture

Three-tier system with Tier-1 for financial authority, Tier-2 for cognition, and clear separation of concerns.

Agentic Cognitive Fabric

Bounded AI coordination with role-scoped capabilities, memory partitioning, and evidence-based decision making.

Deterministic Canvas

Reproducible market intelligence scratchpad for agentic use with causal fact tracking.

Evidence-Driven

Immutable evidence bundles, hash-chained ledgers, and comprehensive audit trails.

Target Architecture

Architecture Principles

  • One canonical financial history and one execution owner
  • Governed, evidence-driven agentic trading platform
  • Production and simulation share code but not authority
  • Deterministic Market Canvas with full scratchpad capability
  • Bounded AI cognition without financial credentials
  • Research-side RL with governed promotion

Three-Tier Structure

  • Tier-1: Financial authority, policy/admission, execution gateway, and ledger management
  • Tier-2: AI cognition, tool use, research coordination, memory management
  • Shared Code: Deterministic engine with separate instances for live and simulation

Architecture Strengths

  • Sole execution ownership eliminates ambiguity in the kernel
  • Hash-chained ledger provides tamper-evident financial records
  • Clear Tier1/Tier2 separation prevents cognition from direct execution
  • Shared code between production and simulation reduces divergence
  • Supervisor is proposal-only, preserving kernel authority
  • Immutable research bundles with content hashes ensure reproducibility
  • WAL-aware backup ensures consistent recovery points
  • Versioned planning port enables safe evolution

Critical Gaps

  • Single Tier-1 writer; measure availability needs before proposing redundancy
  • Missing idempotency guarantees at transaction boundaries
  • Single broker vendor dependency (OpenAlgo) with no fallback
  • Ambiguous result handling lacks formal state machine
  • Simulation disarming not formally verified
  • No backpressure mechanism in market data pipeline
  • Owner governance is single-person dependency
  • SQLite scalability ceiling for growing transaction volumes

High-level production path

OpenAlgo market and account interfaces provide observations.
Canonical market storage and evidence feed MarketInputSource and MarketView; immutable historical bundles can also feed MarketView.
Strategies and workers produce typed intents; bounded AI entry review can advise or reject, but does not own execution.
Gateway and ownership checks precede registry/reservation handling and the authenticated Tier1 boundary.
Tier1 coordinates financial effects, ledger records, and projections; reconciliation and protection consume broker, registry, and ledger state.
Replay uses immutable bundles and a no-send adapter; research custody/evaluation feeds governed candidate activation.
Critical boundary

Tier1 execution ownership

Typed intent crosses an authenticated boundary to the Tier1 coordinator. Cognition is advisory; it must not gain direct financial authority through the review flow.

  • Source audit: authority and persistence contracts reviewed.
  • Evidence limit: this page does not demonstrate a live deployment or failover behavior.
Critical boundary

Broker, registry, and ledger reconciliation

Broker effects, local ownership records, and financial ledger/projections can represent different stages of the same action; recovery must join them by stable identity.

  • Code-audited concerns include ACK persistence and intent settlement (F1/F2).
  • No duplicate broker send or financial loss was established.
Critical boundary

Replay and research isolation

Replay should use immutable evidence and a no-send boundary. Research custody, evaluation, candidate freezing, and activation are separate governance stages.

  • Target policies and activation controls remain proposals/open decisions where not verified.
  • See Code Audit and the Master README for scope and evidence.

Production and simulation boundary

Source-audit documentation describes shared deterministic logic with distinct production and replay inputs/adapters. Treat the isolation statement as a design boundary in the audited code; formal deployment-level verification was not established by this audit.
